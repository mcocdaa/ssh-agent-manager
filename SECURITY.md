# Security Policy

## Reporting a Vulnerability

If you discover a security issue in `ssh-agent-manager`, please do not disclose it in a public issue before remediation. Report it privately via GitHub Security Advisories or contact the repository maintainer directly.

## Security Model & Best Practices

- **Private key storage**: Keys generated by `init.sh` / `init.ps1` are stored under `.ssh_keys/`, which is excluded via `.gitignore`.
- **Permissions**: `.ssh_keys/` is restricted to `0700`, private keys to `0600`, and `.pub` files to `0644`.
- **Passphrases**: Using a strong passphrase on ed25519 keys is recommended; `init.sh` and `init.ps1` explicitly warn if an empty passphrase is used.
- **Input validation & command safety**: Hostnames, usernames, and aliases are validated to reject whitespace, quotes, and shell metacharacters. On Windows, public keys are streamed over `ssh` stdin (`tr -d '\r' >> ~/.ssh/authorized_keys` under `umask 077`) rather than interpolated into a remote shell command.
- **Session isolation**: `setup.sh` only terminates a freshly spawned `ssh-agent` process and falls back to `ssh-add -d` for pre-existing agents; `setup.ps1` unloads only the active key without stopping or disabling the system `ssh-agent` service.
